# Шпаргалка: как выполнено задание «ЧитайГород»

Основа — вариант **В1_КОД 09.02.07-2-2026-БУ**, модули 1–3 и выданные ресурсы. Пиши и проверяй по этапам: сначала данные и таблицы, затем связи, затем интерфейс.

## 1. Разобрать условие и файлы заказчика

1. Открой задание и выпиши роли: гость, авторизованный клиент, менеджер, администратор.
2. Выпиши поля карточки: фото, артикул и название, категория, описание, производитель, поставщик, цена, единица, склад, скидка.
3. Перечисли действия: показ списка; для менеджера — поиск/сортировка/фильтр и просмотр заказов; для администратора — добавление/изменение/удаление товаров и заказов.
4. Посмотри листы Excel. В выданных файлах:
   - `Tovar.xlsx`: листы `Product`, `Supplier`, `Manufacturer`, `Category`;
   - `User_import.xlsx`: `User`, `Role`;
   - `Order_import1.xlsx`: `Order`, `Fio`, `Count`, `Status`;
   - `PickUpPoint_import1.xlsx`: `PickUpPoint`;
   - `1.jpg`–`20.jpg`, `picture.png`, `icon.png`, `icon.ico` — фото, заглушка, логотип и иконка.
5. Сверь строки и имена столбцов с книгой Excel до импорта. Например, лист Product содержит `Id`, `Article`, `ProductName`, `Price`, `SupplierId`, `ManufacturerId`, `CategoryId`, `Skidka`, `Sklad`, `Description`, `Photo`.

## 2. Спроектировать 3НФ

Смысл нормализации: каждое описание объекта хранится один раз; дочерняя запись ссылается на родителя по ID.

1. Создай справочники `Role`, `Supplier`, `Manufacturer`, `Category`, `OrderStatus`, `PickupPoint`.
2. Создай `User` с внешним ключом `role_id` — роль пользователя не копируется текстом в каждой учётной записи.
3. Создай `Product`: основные свойства товара и внешние ключи на поставщика, производителя, категорию.
4. Создай `Customer` отдельно от `User`: в исходных файлах покупатели заказа и пользователи системы — разные наборы данных.
5. Создай `ShopOrder`: дата, срок доставки, пункт выдачи, клиент, код получения, статус.
6. Создай `OrderItem`: связь заказа и товара плюс количество. Один заказ может включать несколько товаров, а один товар — входить в разные заказы; поэтому нужна таблица-связка.
7. Включи первичные ключи, внешние ключи и ссылочную целостность. Для товара запрети отрицательные цену и остаток. Для строк заказа запрети удалять используемый товар (`ON DELETE RESTRICT`); для удаления заказа удаляй его строки (`ON DELETE CASCADE`).
8. Схема и связи показаны в `ER_диаграмма.pdf`.

**Почему это 3НФ:** название категории находится в Category, а не повторяется у каждого товара; имя поставщика хранится в Supplier; ФИО клиента не дублируется в заказе; состав заказа вынесен в OrderItem. Непосредственно в Product остаются свойства конкретного товара.

## 3. Как данные из Excel попали в базу приложения

Рабочая программа использует SQLite — встроенную в Python базу. Однократную загрузку выполняет `import_data.py` через `openpyxl`; этот файл можно прочитать сверху вниз.

1. `database.initialize()` создаёт таблицы и включает `PRAGMA foreign_keys = ON`.
2. Если таблица Product пустая, вызывается `load_excel_data(connection)`.
3. `rows("Tovar.xlsx", "Supplier")` открывает нужный лист, берёт первую строку как имена столбцов и собирает каждую следующую строку в словарь. Пустые строки пропускаются.
4. Сначала загружаются справочники и пользователи: роли, поставщики, производители, категории, покупатели, статусы, пункты выдачи.
5. Потом загружаются товары. Например, Excel `ProductName` записывается в поле БД `Product.name`, `Price` — в `Product.cost`, `CategoryId` — во внешний ключ `Product.type_id`, `Sklad` — в `Product.stock`.
6. Имена фотографий из Excel, например `1.jpg`, копируются в `images/`. В Product.image записывается относительный путь `images/1.jpg`, а не двоичный файл фотографии.
7. Затем загружаются заказы и их строки. `Order.Fio_Id` ссылается на `Customer.customer_id`; лист `Count` превращается в строки `OrderItem`.
8. После загрузки проверь количество строк и внешние ключи. Здесь ожидаются: 20 товаров, 18 поставщиков, 10 производителей, 4 категории, 10 пользователей, 10 заказов, 20 строк состава заказа, 36 пунктов выдачи.

Не импортируй все данные в одну широкую таблицу: так повторялись бы адреса пунктов выдачи, названия категорий и производители.

## 4. Если импортировать эти Excel-листы вручную в Microsoft Access

Это отдельная инструкция для Access. В проекте приложения БД SQLite, поэтому Access не является подключённой к приложению базой.

1. Создай пустую базу Access `ChitaiGorod.accdb`.
2. Выбери **Внешние данные → Новый источник данных → Из файла → Excel**.
3. Укажи `Tovar.xlsx`, затем **Импортировать исходные данные в новую таблицу**. Поставь «Первая строка содержит заголовки столбцов».
4. Импортируй каждый лист отдельно в промежуточные таблицы, например `Импорт_Product`, `Импорт_Supplier`, `Импорт_Manufacturer`, `Импорт_Category`. Повтори для `User_import.xlsx`, `Order_import1.xlsx`, `PickUpPoint_import1.xlsx`.
5. Для ID выбери тип «Числовой — Длинное целое» (или используй исходный ID как первичный ключ). Логин, пароль, артикул, почтовый индекс и код получения задай как «Короткий текст», даже если часть значений выглядит как число. Даты — «Дата/время», цена — «Денежный», скидка — «Числовой», остаток/количество — «Числовой — Длинное целое».
6. Не оставляй служебные импортные листы основной базой: перенеси записи в нормализованные таблицы по схеме ER-диаграммы. Сначала справочники, затем товары/пользователи/покупатели, после этого заказы и состав заказа.
7. В `Product.Image` сохрани путь, например `images\1.jpg`. Скопируй фото в папку рядом с базой. Не вставляй картинку вместо пути: задание требует хранить путь к изображению.
8. Открой **Работа с базами данных → Схема данных**. Добавь таблицы и перетащи PK родителя на соответствующий FK дочерней таблицы. Отметь **Обеспечение целостности данных**. Каскадное удаление включи только для Order → OrderItem.
9. Проверь связи: попробуй добавить товар с несуществующим CategoryId — Access должен запретить. Попробуй удалить товар, входящий в заказ — Access должен запретить.
10. Сохрани схему данных в PDF. В приложении к заданию скрипт импорта автоматизирован и повторяем; в Access эти пункты выполняются в мастере импорта и окне связей.

## 5. Как работает интерфейс и алгоритмы

1. Запуск открывает окно входа; пользователь проверяется запросом по логину и паролю.
2. Неверные данные показывают понятное сообщение. Кнопка гостя открывает только просмотр каталога.
3. Роль хранится в `current_user`. По роли приложение показывает или скрывает элементы управления; менеджер не может вызвать формы администратора.
4. Для менеджера и администратора при вводе поиска, выборе сортировки или фильтра сразу вызывается `refresh_products()`.
5. SQL ищет одновременно в артикуле, названии, единице измерения, описании, категории, производителе и поставщике.
6. Скидочный диапазон применяется в SQL и вместе с поиском; выбранная сортировка не сбрасывается.
7. Итоговая цена: `цена × (100 − скидка) / 100`. Скидка больше 25% — бирюзовый фон `#23E1EF`; нулевой остаток — серый. В карточке исходная цена перечёркнута красным, итоговая показана рядом.
8. Форма товара проверяет обязательные поля, цену, скидку и остаток. При выборе нового фото оно сохраняется в `images/` размером 300 × 200 px; в БД записывается относительный путь. Старый файл удаляется, только если на него больше нет ссылок.
9. Перед удалением товара проверяется внешний ключ. Если товар используется в заказе, SQLite отклоняет удаление и приложение показывает сообщение.
10. `Блок-схема.pdf` показывает алгоритм приложения от запуска до выполнения действия по роли.

## 6. Проверка перед сдачей

Выполняй действия по одному и проверяй ожидаемый результат:

1. Запусти `main.py`; проверь логотип и заголовок.
2. Войди как `1 / 1` — должен появиться администратор. Введи неверный пароль — ошибка входа, приложение не закрывается.
3. Войди как гость и как `3 / 3` — каталог доступен, но фильтры и кнопки управления отсутствуют.
4. Войди как `2 / 2` — поиск по названию/описанию, сортировка цены и остатка, фильтр скидки доступны и работают без кнопки.
5. Найди товар со скидкой 30%: строка бирюзовая; выбери её — старая цена красная и перечёркнута, новая цена рядом.
6. Найди товар с нулевым остатком: строка серая.
7. Администратором добавь товар, укажи цену с копейками и загрузи изображение. Проверь наличие файла 300 × 200 в `images/` и путь в таблице Product.
8. Измени товар: поля формы должны загрузиться из БД. Замени фото и проверь удаление старого файла, если он больше не используется.
9. Попробуй удалить товар, который указан в одном из 10 исходных заказов — удаление запрещено. Добавленный товар без заказа можно удалить.
10. Менеджером открой «Заказы» — список виден, кнопок изменения нет. Администратором добавь/измени/удали тестовый заказ.
11. Закрой приложение и запусти повторно: введённые товары и изменения должны сохраниться.
12. Для требуемого в задании документа со скриншотами сделай реальные снимки окон в PyCharm/Windows после этих тестов и вставь в отдельный DOCX. Не используй макеты вместо снимков работающей программы.

## Как выучить код небольшими кусками

Не пытайся заучить все строки интерфейса. Запоминай ход данных и по одному ключевому методу:

1. `main()` запускает `database.initialize()`, потом окно `App`.
2. `App.login()` проверяет логин/пароль; `open_shop()` строит каталог для определённой роли.
3. `database.products()` делает один SELECT с JOIN-ами, поиском, фильтром и сортировкой.
4. `refresh_products()` берёт результат запроса и выводит строки в таблицу; там же задаются цвета скидки и отсутствия товара.
5. `product_form()` собирает значения, проверяет их и вызывает `database.save_product()`.
6. `load_excel_data()` объясняет импорт; `schema.sql` — источник структуры и ограничений.

Учи сначала цепочку **ввод → функция → запрос → результат на экране**. Кнопки и оформление можно читать отдельно; важнее понимать, какие данные получает функция и что она возвращает.
