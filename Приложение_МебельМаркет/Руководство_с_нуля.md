# Руководство с нуля — вариант № 5 «Мебель»

Это порядок действий для нового Windows-ПК и чистого рабочего проекта. Вариант сделан на Python + Tkinter + SQLite. SQLite — файл базы рядом с кодом; отдельный сервер или Access этому приложению не нужны.

## 1. Что установить заранее

1. Python 3.11 x64 с `python.org`; в установщике включить **Add Python to PATH** и **tcl/tk**.
2. PyCharm с официального сайта JetBrains.
3. Excel/Word или LibreOffice для таблиц и отчёта; архив Windows можно распаковать стандартно или через 7-Zip.
4. Скачать проектный ZIP и распаковать его, например в `C:\DEMO\Приложение_МебельМаркет`. Не открывать код прямо внутри ZIP.

Проверить в PyCharm → Terminal:

```powershell
python --version
python -m pip --version
python -m tkinter
```

Последняя команда должна открыть небольшое тестовое окно. Закрыть его.

## 2. Создать окружение и поставить библиотеки

Откройте именно папку `Приложение_МебельМаркет` в PyCharm. Терминал должен быть в корне проекта, рядом с `main.py` и `requirements.txt`.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Если PyCharm уже создал `.venv`, не выполняйте первую строку повторно. Пакеты `openpyxl` и `Pillow` нужны приложению для Excel и фотографий; `sqlite3`, `tkinter`, `pathlib` и `unittest` входят в Python.

## 3. Что изучить до кода на экзамене

1. Внимательно прочитать условие и выписать роли, атрибуты товара, права и специальные правила.
2. Проверить исходные файлы Excel и ресурсы. В присланных фотографиях нет приложений 1–3; в этом проекте Excel помечен как демонстрационный.
3. Спроектировать таблицы и связи до программирования. Сначала справочники, затем зависимые сущности.
4. Сохранить ER-модель в PDF; после определения процесса сделать блок-схему работы приложения.
5. Создать схему БД, импортировать данные и проверить ключи.
6. Разрабатывать интерфейс итерациями: вход → каталог → роли → поиск/фильтры/сортировка → CRUD.
7. Провести автоматические и ручные проверки; только затем делать настоящие скриншоты и отчёт.

## 4. Как устроена БД

- `Role`, `User` — роли и учётные записи.
- `Category`, `Manufacturer`, `Supplier`, `Unit` — независимые справочники.
- `Product` — товар с внешними ключами на справочники.
- `Warehouse`, `Inventory` — склады и количество конкретного товара на конкретном складе.
- `Customer`, `OrderStatus`, `ShopOrder`, `OrderItem` — покупатели, заказы и состав заказа.

Таблица `Inventory` нужна потому, что у одного товара остатки могут быть распределены по нескольким складам. Общий остаток каталога равен сумме строк по складам. `OrderItem` хранит товары заказа отдельно; внешний ключ не даёт удалить товар, используемый в заказе.

## 5. Запуск и тесты

Первый запуск создаёт `mebelmarket.db` и переносит демонстрационные записи из `import/Furniture_demo_import.xlsx`:

```powershell
.\.venv\Scripts\python.exe main.py
```

Выполнить автоматические тесты:

```powershell
.\.venv\Scripts\python.exe -m unittest -v
```

Проверить синтаксис:

```powershell
.\.venv\Scripts\python.exe -m py_compile main.py database.py import_data.py test_database.py
```

Демо-логины и пароли приведены в `README.md`. Входите под каждой ролью: гость, клиент, менеджер, администратор. Проверьте кнопку выхода, имя/роль в шапке, права в каталоге и CRUD заказов.

## 6. Ручной сценарий перед сдачей

- Гость и клиент видят каталог, но не видят поиск/фильтр/сортировку.
- Менеджер видит эти инструменты и заказы, но не кнопки изменения.
- Администратор управляет товарами и заказами.
- Товар со скидкой ровно 15% не должен считаться скидкой `>15%`; товар с 16% и выше имеет фон `#008080`.
- Нулевой остаток серый, даже если скидка больше 15%.
- Исходная цена зачёркнута красным, итоговая указана рядом чёрным.
- У товара с несколькими складами суммы на карточке совпадают с суммой по `Inventory`.
- Нельзя удалить мебель, присутствующую в заказе.

## 7. Финальная сдача

1. Выполнить тесты и убедиться, что ошибок нет.
2. Убедиться, что есть `schema.sql`, импортный Excel, база `.db`, `main.py`, `database.py`, `import_data.py`, PDF-диаграммы и инструкция.
3. Открыть `Отчёт_скриншоты_ШАБЛОН.docx` и вставить реальные снимки приложения. Плейсхолдеры заменить; не выдавать их за снимки.
4. Запаковать папку проекта в ZIP и проверить, что архив открывается. Сохранить копию на отдельный носитель.

## Что сделать в экзаменационные 90 минут

На фотографиях указано: модуль 1 — 50 минут, модуль 2 — 40 минут.

- **Первые 50 минут:** выписать сущности/поля, создать схему с PK/FK, импортировать данные, проверить количество строк и целостность, сохранить SQL и ER PDF.
- **Следующие 40 минут:** блок-схема алгоритма, подключение БД к UI, вход/гость/роли, каталог и отображение скидки/остатка; затем быстрый прогон ключевых сценариев.
- Оставлять последние 3–5 минут на сохранение файлов и проверку имён/форматов. Если на экзамене выданы другие Excel и приложения, сначала работать с ними, а не с демоданными проекта.
