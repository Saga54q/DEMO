# Шпаргалка — Вариант 2 «ВелосипедДрайв»

Ориентир — Вариант 2 из папки `ДЭ прграммисты 1-2.06/2`, модули 1–3 и ресурсы вложенного ZIP. **Вариант 2 отличается от Варианта 1 не только названием:** тут велосипеды, иной стиль, порог скидки 15%, другие диапазоны фильтра и дополнительная сортировка по скидке.

## 1. Сначала читаю условие и ресурсы

1. Предметная область из DOCX: ООО «ВелосипедДрайв», магазин велосипедов.
2. Роли те же: гость и клиент только смотрят; менеджер ищет/фильтрует/сортирует и смотрит заказы; администратор управляет товарами и заказами.
3. Отдельно выписываю отличия Варианта 2:
   - скидка **больше 15%** → фон `#483D8B`;
   - фильтр: `0–11,99%`, `12–18,99%`, `19% и более`;
   - сортировка: цена, остаток и скидка (по возрастанию/убыванию);
   - стиль: Arial, белый, `#6A5ACD`, акцент `#4B0082`.
4. В исходном ZIP нахожу `Tovar.xlsx`, `user_import.xlsx`, таблицу заказов, список адресов пунктов выдачи, 10 фотографий, логотип и заглушку.
5. В таблице товаров нет готовых ID справочников: поставщики, производители и категории создаются как отдельные справочники, а их ID назначаются при импорте.

## 2. Проектирую таблицы в 3НФ

Используются те же сущности, что и в приложении: `Role`, `User`, `Supplier`, `Manufacturer`, `ProductType`, `Product`, `Customer`, `PickupPoint`, `OrderStatus`, `ShopOrder`, `OrderItem`.

1. `Product` хранит конкретный велосипед и FK на категорию, производителя и поставщика.
2. `User` отдельно от `Customer`: учётные записи сотрудников/клиентов и покупатели, указанные в заказах, поступают из разных таблиц.
3. `ShopOrder` хранит дату, дату доставки, пункт, клиента, код и статус.
4. `OrderItem` связывает заказ с товаром и количеством. Состав не хранится строкой в заказе.
5. Внешние ключи проверяются SQLite; заказ удаляется вместе со строками, но товар из существующего заказа удалить нельзя.
6. Поля скидки, цены и остатка имеют проверки допустимых значений. `ER_диаграмма.pdf` содержит PK/FK и связи.

## 3. Как переносились Excel-данные в базу приложения

Здесь рабочая база SQLite; при первом запуске `database.initialize()` запускает `import_data.load_excel_data()`.

1. `Tovar.xlsx` читается через `openpyxl`; каждая строка становится словарём по заголовкам.
2. Из названий поставщика, производителя и категории создаются уникальные списки и таблицы-справочники. Например, текст `Slash` остаётся в Manufacturer один раз, а Product хранит только `manufacturer_id`.
3. Лист пользователей содержит роль строкой. Уникальные роли заносятся в Role, а User получает внешний ключ на Role.
4. Файл пунктов выдачи состоит из строк-адресов без строки заголовков. Номер строки становится `point_id`, адрес разбивается на индекс, город, улицу и дом.
5. В книге заказов товары записаны строкой парами `артикул, количество`. Импорт делит строку по запятым, находит каждый артикул в Product и создаёт строки `OrderItem`.
6. Даты Excel переводятся в ISO `ГГГГ-ММ-ДД`; статусы очищаются от крайних пробелов.
7. В исходном заказе №7 дата `30.02.2023` невозможна. Для загрузки она нормализована до `28.02.2023` — последнего календарного дня февраля 2023 года. Исправление явно печатается при импорте.
8. Фотографии копируются в `images/` и перекодируются в настоящий JPEG; в Product.image сохраняется путь вроде `images/1.jpg`. Для товара без фото используется `picture.png`.
9. После загрузки проверяются количество строк и `PRAGMA foreign_key_check`.

## 4. Если делать импорт в Microsoft Access вручную

Приложение подключено к SQLite, но последовательность для переноса **тех же** данных в Access такая:

1. Создать пустую `VeloDrive.accdb`.
2. В Access выбрать **Внешние данные → Новый источник данных → Из файла → Excel**.
3. Сначала импортировать `Tovar.xlsx` в промежуточную таблицу, отметить «Первая строка содержит заголовки». Повторить для `user_import.xlsx`, файла заказов и таблицы пунктов выдачи.
4. При импорте задавать типы осознанно: цена — Денежный; скидка — Числовой; остаток — Длинное целое; даты — Дата/время; артикул/логин/пароль/индекс/код — Короткий текст.
5. Создать справочники Supplier, Manufacturer, Category и Role. Перенести уникальные названия по одному разу, назначить PK, затем добавить соответствующие ID в Product/User.
6. Для файла пунктов выдачи создать ID по номеру исходной строки. Адрес разделить на индекс/город/улицу/дом; у записи, где дом не задан, оставить пустое значение.
7. Состав заказа `артикул, количество, артикул, количество` разбить на отдельные записи OrderItem. Сначала получить ID товара по артикулу.
8. Создать таблицы нормализованной схемы, перенести данные из промежуточных таблиц в порядке: справочники → пользователи/товары/клиенты/пункты → заказы → состав заказа.
9. В окне **Схема данных** связать PK с FK и включить «Обеспечение целостности данных». Сохранить ER-схему в PDF.
10. Пункт №7 с невозможной датой исправить и записать исправление в пояснение к импорту.

## 5. Приложение и проверка требований

1. `main.py` сначала открывает вход; неверные данные дают сообщение, гость входит кнопкой.
2. ФИО и роль показываются в верхней части окна. Возможности скрываются/показываются по роли.
3. Для менеджера/администратора поиск выполняется по артикулу, названию, единице, описанию, категории, производителю и поставщику.
4. Поиск, диапазон скидки и сортировка сохраняются вместе и обновляют список сразу.
5. Цвет строки — `#483D8B` только если скидка `> 15`; если остаток ноль, строка серая.
6. Итоговая цена: `цена × (100 − скидка) / 100`. Обычная цена при скидке перечёркнута и красная; итоговая цена рядом.
7. Администраторская форма проверяет ввод, хранит путь фото, масштабирует загружаемое фото до 300 × 200 px, не допускает два окна редактирования.
8. Удаление товара из заказа блокируется внешним ключом; после сохранения каталог перечитывается.
9. Блок-схема — в `Блок-схема.pdf`; проверить БД можно командой `python -m unittest -v`.
10. `Отчёт_скриншоты_ШАБЛОН.docx` заполнить настоящими снимками после запуска приложения на Windows.

## Выучить в правильном порядке

`условие → отличия варианта → сущности → ключи → импорт справочников → импорт товаров → разбор заказов → роли → таблица каталога → поиск/сортировка/фильтр → CRUD администратора → тесты`.
