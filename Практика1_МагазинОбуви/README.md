# Практика 1 — «Магазин обуви» (полный результат Задания 1)

Полностью готовая рабочая база данных по образцу задания **«Разработка базы данных
средствами СУБД»** (КИМ 09.02.07-2-2027 Том 1, стр. 30–31). СУБД — Microsoft Access.

## Состав пакета

| Файл | Что это |
|---|---|
| `МагазинОбуви.accdb` | **Готовая база Access**: 7 таблиц, данные, ключи, 6 связей со ссылочной целостностью, изображения моделей (поле «Вложение») |
| `СхемаДанных.pdf` | ER-диаграмма (таблицы, атрибуты, ключи, связи) — обязательный результат по заданию |
| `sql/МагазинОбуви.sql` *(в корне репозитория)* | Скрипт базы данных с данными (DDL + INSERT) — формат результата, допустимый по КИМ |
| `import/*.xlsx` | Исходные данные «заказчика» (для импорта): 7 файлов |
| `images/*.jpg` | Изображения товаров (загружены в поле «Вложение» таблицы «Модели») |
| `ШПАРГАЛКА.md` | Чеклист действий в Access (для разбора и тренировки) |

## Как требования КИМ выполнены

| Требование задания (стр. 30–31) | Как реализовано |
|---|---|
| БД в выбранной СУБД | `МагазинОбуви.accdb` (Microsoft Access) |
| Третья нормальная форма | 7 таблиц без дублирования: каждый факт хранится один раз. ФИО клиента — только в «Клиентах»; цена продажи — в «СоставЗаказа», текущая цена — в «Модели» |
| Ссылочная целостность | Все 6 связей — с «Обеспечение целостности данных» (проверено: мусорные записи отвергаются) |
| Первичные ключи | `ID_*` (Счётчик) в каждой таблице |
| Внешние ключи | `ID_Клиента`, `ID_Заказа`, `ID_Позиции`, `ID_Модели`, `ID_Категории`, `ID_Производителя` (Числовой, Длинное целое) |
| Ограничения внешних ключей «по характеру предметной области» | Каскадное **обновление** — везде; каскадное **удаление** — только Заказы→СоставЗаказа (удаление заказа удаляет его строки); удаление клиента/модели с продажами запрещено. Плюс уникальный индекс «модель + размер» и правила проверки «Количество ≥ 0», «Цена ≥ 0» |
| Согласованная схема именования | Таблицы — множественное число; поля — CamelCase; ключи всегда `ID_Сущность` (одинаково в родительской и дочерней таблицах) |
| Каталог: количество по сочетанию «модель + размер» | Таблица `ТоварныеПозиции` |
| Для каждой модели сохраняется изображение | Поле `Изображение` (тип **Вложение**), картинки загружены в базу |
| Список заказов: дата заказа, ФИО клиента | `Заказы` + связь с `Клиенты` (ФИО берётся через связь, не дублируется) |
| Управление заказами (выбор нескольких пар) | `СоставЗаказа`: заказ содержит любое число строк «позиция + количество + цена» |
| ER-диаграмма в PDF: таблицы, связи, атрибуты, ключи | `СхемаДанных.pdf` |
| Импорт данных заказчика | Данные из `import/*.xlsx` перенесены в базу (файлы приложены) |
| Сохранить результат: скрипт БД с данными | `sql/МагазинОбуви.sql` + файл `МагазинОбуви.accdb` |

## Структура базы (7 таблиц, все связи 1:N)

```text
Клиенты (1) ────────< (N) Заказы (1) ────────< (N) СоставЗаказа (N) >──────── ТоварныеПозиции
                                                       (N) >──────────────── Модели (N) >──── (1) Категории
                                                                                     (N) >──── (1) Производители
```

| Таблица | Записей | Назначение |
|---|---|---|
| Клиенты | 5 | покупатели |
| Категории | 4 | справочник категорий обуви |
| Производители | 4 | справочник производителей |
| Модели | 6 | каталог: модель, состав, описание, цена, изображение |
| ТоварныеПозиции | 15 | склад: модель + размер + доступное количество |
| Заказы | 5 | заказы: клиент + дата |
| СоставЗаказа | 9 | строки заказов: позиция + количество + цена продажи |

## Как проверить базу (5 минут в Access)

1. Открой `МагазинОбуви.accdb` → **Работа с базами данных → Связи**: 6 связей, все со «стелсиком» целостности (значок ∞).
2. Открой `Модели` → поле `Изображение` → двойной клик: фото модели открывается.
3. `СоставЗаказа` → попробуй вписать строку с `ID_Заказа = 77` → **Access запретит** (ссылочная целостность).
4. `Клиенты` → попробуй удалить Иванова (заказы есть) → **Access запретит** (каскада нет — история сохраняется).
5. `Заказы` → удали заказ №5 → его строки из `СоставЗаказа` исчезнут (каскадное удаление).

## Как воспроизвести базу (для разбора)

База собирается автоматически скриптом `tools/СборкаБД.ps1` (движок DAO):
пустой `.accdb` → структура и данные из `sql/МагазинОбуви.sql` → связи → вложения → проверки.
Сборка запускается GitHub Actions (`.github/workflows/build-accdb.yml`) на Windows-раннере
и выкладывается артефактом `МагазинОбуви`.
